Project Overview

For my Software Validation class we were tasked with setting up Appium Inspector and writing test scripts in Python to automate testing of an Android application. The tests included navigating through the app, changing settings, creating events and tasks, and handling various pop-ups and permissions.

🏗️ Technical Architecture
The automation framework uses Appium as the core testing platform for Android mobile automation. Python serves as the scripting language for writing test cases, leveraging the Appium Python client library for WebDriver interactions. The Android application under test runs on Android Studio's built-in emulator, which communicates with the Appium server to execute commands. Appium Inspector is used for element inspection, allowing identification of UI elements through various locator strategies (ID, XPath, accessibility ID, etc.). The test scripts initialize a driver session with desired capabilities specifying the app package, activity, and device configuration. Tests automate user interactions like tapping, swiping, text input, and navigation while handling dynamic elements such as permissions dialogs and pop-ups. The framework captures screenshots at various test stages for validation and documentation purposes, testing multiple app activities including Main, Settings, Event creation, Task management, Event Type management, and Time Zone selection.

💡 Challenges & Solutions
Challenge: Setting up the Appium environment and configuring the connection between Appium Server, Android Studio Emulator, and Python test scripts.

Solution: Followed a systematic setup process: installed Appium Server, configured Android SDK paths, set up the Android Studio Emulator with appropriate API levels, and installed the Appium Python client library. Used Appium Inspector to verify the connection and inspect app elements before writing test scripts. Configured desired capabilities correctly to specify the app package, activity, and automation framework (UiAutomator2).

Challenge: Handling dynamic Android permissions dialogs and pop-ups that appeared unpredictably during test execution.

Solution: Implemented explicit waits using WebDriverWait with expected conditions to handle timing issues. Created reusable functions to detect and handle permission dialogs by locating the "Allow" button using standard Android permission controller IDs. Added try-except blocks to gracefully handle cases where pop-ups might not appear, ensuring test continuity.
