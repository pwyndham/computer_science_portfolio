Project Overview

The Shadow's Gaze was my final project for my Game Development class at UTSA. This was a solo project I had which I had to create all assets, scripts and everything associated with the project. I used Figma to get the foundation logic for the project. I had character classes laid out, logic flow design, inventories and interactions. I used Blender to create the 3D models for character, enemy and environment assets. For the animations I used the Unity Editor to create animation states. The gameplay was fully created in Unity with C# scripts. The game is a Rogue-like dungeon crawler where the player picks a class (Rogue, Mage, Warrior) and fights through procedurally generated levels with enemies and bosses. The player can collect coins for potions, and upgrade his character.

Key Features

  • Three playable character classes (Rogue, Mage, Warrior) with unique abilities and playstyles
  • Procedurally generated dungeon levels for unique gameplay experiences
  • Combat system with enemy AI and boss encounters
  • Inventory system for managing items and potions
  • In-game shop with currency-based purchasing system
  • Character progression and upgrade mechanics
  • Custom 3D models for characters, enemies, and environments created in Blender
  • Animation state machine system using Unity's Animator
  • All game logic implemented in C# scripts
  • Designed game architecture and flow using Figma for planning
🏗️ Technical Architecture
The game is built entirely in Unity Engine using C# for all game logic and mechanics. The development pipeline started with Figma for design planning, including character class layouts, logic flow diagrams, and UI/UX mockups for inventory and interaction systems. All 3D assets (characters, enemies, environment pieces) were modeled from scratch in Blender and imported into Unity. Animation states were created and managed through Unity's built-in Animator component. The procedural level generation system uses a pseudo wave function collapse algorithm to create relatively unique dungeon layouts each playthrough. The game follows object-oriented programming principles with modular C# scripts for player controllers, enemy AI, inventory management, and shop systems. VSCode was used as the IDE for script development.

💡 Challenges & Solutions
Challenge: Creating all game assets from scratch as a solo developer, including 3D models, animations, and scripts, within the semester timeframe.

Solution: Started with bulk project planning in Figma to establish clear design goals and workflow. Created a modular development pipeline: designed concepts in Figma, modeled in Blender, then integrated into Unity. This systematic approach ensured efficient use of time and maintained consistency across all assets.

Challenge: Implementing procedural level generation that creates playable dungeons while maintaining performance.

Solution: Studied and developed an algorithm that generates dungeon layouts based on predefined room templates and connection rules. Used object pooling to manage instantiated level pieces efficiently, preventing memory issues during runtime.

Challenge: Balancing three different character classes to ensure each felt unique but equally viable.

Solution: Created distinct stat distributions and playstyle mechanics for each class (Rogue: high speed/low health, Mage: ranged attacks/medium stats, Warrior: high health/slower movement).
