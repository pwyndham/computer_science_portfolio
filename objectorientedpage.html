Command and Handler Design Patterns

Command and Handler design patterns project for Object Oriented Systems class at UTSA

Project Overview

For my Object Oriented Systems class we had a command, handler, memento design pattern project. Where we were to integrate these 3 design patterns with each other to get the expected output. The handlers transfered ownerhsip of the commands to execute them. The memento pattern was used to store the state of the objects before and after the commands were executed.

Key Features

  • Command Pattern implementation with Command interface and concrete command classes (Select, Delete, etc.)
  • Chain of Responsibility Pattern with Handler interface for command processing
  • Memento Pattern for state management and undo/redo functionality
  • Shape-specific handlers (Circle Handler, Select Handler) for targeted command execution
  • Handler chain for transferring command ownership and execution
  • State preservation before and after command execution using Memento
  • Terminal-based shape editor application interface
  • Command input processing and validation system
  • UML class diagram designed in Lucid Chart
  • Integration of three design patterns working cohesively
🏗️ Technical Architecture
The application demonstrates a sophisticated integration of three classic Gang of Four design patterns. The Command Pattern encapsulates requests as objects (SelectCommand, DeleteCommand, etc.), allowing for parameterization and queuing of operations. The Chain of Responsibility Pattern is implemented through a handler chain where each handler (CircleHandler, SelectHandler) can process or pass commands to the next handler in the chain, enabling flexible command ownership transfer and execution. The Memento Pattern captures and externalizes object state without violating encapsulation, storing snapshots before and after command execution to enable undo/redo functionality. The architecture was designed in Lucid Chart with comprehensive UML class diagrams showing relationships between Command, Handler, and Memento components. The terminal-based shape editor serves as the client, coordinating these patterns to provide a robust, extensible editing system. VSCode was used for all implementation work.
💻 Code example
ShapeEditor.java Java / Object-Oriented Design 
package hw3;

import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

import com.example.Handler;
import com.example.Message;
import com.example.Handlers.*;

public class ShapeEditor {

    public static void main(String[] args) {
        if (args.length != 1) {
            System.out.println("Usage: java -cp  hw3.ShapeEditor ");
            return;
        }

        String inputFile = args[0];

        // Setup chain of handlers
        CreateRectangleHandler createRectangleHandler = new CreateRectangleHandler();
        CreateCircleHandler createCircleHandler = new CreateCircleHandler();
        MoveHandler moveHandler = new MoveHandler();
        DrawHandler drawHandler = new DrawHandler();
        DrawSceneHandler drawSceneHandler = new DrawSceneHandler();
        DeleteHandler deleteHandler = new DeleteHandler();
        SelectHandler selectHandler = new SelectHandler();
        UndoHandler undoHandler = new UndoHandler();
        ColorHandler colorHandler = new ColorHandler();

        selectHandler.setNextHandler(moveHandler);
        moveHandler.setNextHandler(colorHandler);
        colorHandler.setNextHandler(deleteHandler);
        deleteHandler.setNextHandler(undoHandler);
        undoHandler.setNextHandler(createRectangleHandler);
        createRectangleHandler.setNextHandler(createCircleHandler);
        createCircleHandler.setNextHandler(drawHandler);
        drawHandler.setNextHandler(drawSceneHandler);

        Handler firstHandler = selectHandler;

        // Read input file
        try (BufferedReader reader = new BufferedReader(new FileReader(inputFile))) {
            String line;
            while ((line = reader.readLine()) != null) {
                line = line.trim();
                if (line.isEmpty()) continue;

                Message message = Message.parseLine(line);
                if (message != null) {
                    firstHandler.handleRequest(message);
                }
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
💡 Challenges & Solutions
Challenge: Integrating three distinct design patterns (Command, Chain of Responsibility, Memento) to work cohesively without creating tight coupling or losing the benefits of each pattern.

Solution: Carefully designed the interfaces and class relationships in Lucid Chart before implementation, ensuring each pattern maintained its core responsibilities while providing clean integration points. The Command pattern encapsulated operations, the Handler chain managed command routing and ownership transfer, and the Memento pattern handled state independently. This separation of concerns allowed each pattern to function properly while working together seamlessly.

Challenge: Implementing the Handler chain to correctly transfer command ownership and execute commands based on type while maintaining flexibility for future command types.

Solution: Designed a flexible handler chain using polymorphism and type checking. Each handler examines the command type and either takes ownership to execute it or passes it to the next handler in the chain. This approach maintains the Open/Closed Principle—new handlers and commands can be added without modifying existing code. The chain terminates gracefully when no handler claims ownership, providing clear feedback to the shape editor.
